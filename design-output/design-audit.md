# Daily Bookkeeping / Rocky 记账 L2 设计诊断

Date: 2026-07-06

## 1. 一句话诊断

当前 UI 已经比早期版本更像一个手机记账 App，但它更像“参考图样式的空壳记账工具”，还不完全像一个可靠、安静、低摩擦、可长期信任的个人账本；最大缺口不是美观，而是“数据可信、可恢复、可追溯”的设计表达太弱。

## 4. Top 3 改造建议

### 1. 首页补“数据安全状态条”

目标：让用户知道当前账本是否可靠。

建议在首页本月已花卡片下方或最近记录上方增加一条低干扰状态：

- 云端已连接 / 本地模式
- 最近同步时间
- 最近备份时间或“立即导出备份”
- 同步失败时显示“未保存到云端，已保留本地副本”

为什么：记账不是普通表单，用户真正关心的是“我记的东西会不会丢”。这条比继续做图表更优先。

### 2. 增加“账本”管理入口，而不是把导出/导入藏在明细区

目标：把查记录、导出、恢复、清空本月变成明确的账本管理能力。

最小方案：

- 底部导航仍保留：首页 / 记一笔 / 统计。
- 首页“最近记录”右上角加“全部”。
- 点“全部”进入或展开“账本明细”视图，顶部固定：
  - 导出备份
  - 导入恢复
  - 清空本月
- 危险动作用确认说明：会先下载备份、清空范围是当前月份。

为什么：当前移动端隐藏 `.list-panel`，导致恢复/导出能力在真实手机主流程不可见。对个人财务 App，这是设计 P0。

### 3. 记录页降低“组件感”，强化“凭证感”

目标：让“记一笔”更像在写一张可信账单，而不是填一个普通表单。

建议：

- 金额区域保留大字号，但增加币种和输入焦点提示，比如 `¥ 0.00`。
- 分类卡片加入真实图标库图标，提高扫视速度。
- 保存后显示明确结果：
  - “已保存到云端”
  - “已保存到本地，云端同步失败可稍后重试”
- 备注字段弱化，但保存反馈强化。

为什么：低摩擦不等于少反馈。财务记录需要“写入成功”的确定感。

## 5. 账务数据可信感 / 恢复感相关设计风险

1. CloudBase 测试域名风险提示会直接削弱信任。
   - 截图 `00-cloudbase-domain-warning.png` 里出现“请勿泄露个人信息、账号密码或进行涉及财产的操作”。
   - 对记账 App 来说，这是强负面信号。
   - 设计上即使 App 内部做得再可信，入口前置风险提示也会抵消一部分信任。

2. 备份和恢复入口在移动端不可见或不可预期。
   - 导出/导入在 `.list-panel`，但移动首页隐藏 `.list-panel`。
   - 用户不知道什么时候可以备份，也不知道误删后怎么恢复。

3. 云端状态缺少“时间证据”。
   - “本地模式 / 未登录”或“云端已连接”只能说明状态，不能说明最近一次成功写入是什么时候。
   - 财务数据更需要最近同步时间、失败状态、备份时间。

4. 清空本月是高风险动作，但在设计层面还没有形成“先备份再执行”的强心智。
   - README 说明会先备份，但界面截图中用户看不到这个承诺。

5. 空状态太轻。
   - “这个月还没有记录”是清楚的，但没有顺手引导“记一笔”或“导入旧账本”。
   - 对迁移后的用户，导入恢复入口应该在空状态出现。

## 6. 不建议改什么

- 不建议现在改整体色彩方向。绿色、白底、轻量阴影符合“安静、低压力、个人账本”。
- 不建议继续追求参考图的视觉还原。当前核心问题不是像不像参考图，而是账本可信感不足。
- 不建议加更复杂图表。没有足够记录前，图表只是装饰。
- 不建议现在做 PC 端复杂适配。项目上下文已经明确手机优先，PC 只要不坏即可。
- 不建议改数据模型、CloudBase 权限、导出恢复逻辑。本次只是设计审计，技术安全另走 CTO/工程任务。

## 7. 是否建议进入实现

建议进入实现，但只做最小范围，不做大改版。

最小实现范围：

1. 首页新增“数据安全状态条”。
   - 显示云端/本地、最近同步、导出备份入口。
2. 移动端新增“账本明细 / 备份恢复”可见入口。
   - 可以先从“最近记录 -> 全部”进入，不一定新增第四个底部导航。
3. 保存后反馈补强。
   - 成功：已保存到云端 / 已保存到本地。
   - 失败：云端未保存，本地已保留，可重试或导出备份。
4. 空状态补两个动作。
   - 记一笔
   - 导入备份

不纳入最小实现：

- 新图表类型
- 周 / 年统计
- 复杂账本搜索
- PC 版重排
- 新品牌视觉系统

## 8. 设计验收标准

实现后需要用手机视口截图验证：

- 首页能看到数据安全状态，不遮挡记账主路径。
- 记录保存后有明确成功或失败反馈。
- 移动端用户能在 2 步内找到导出备份。
- 移动端用户能在 2 步内找到导入恢复。
- 清空本月前的确认说明包含“会先备份”和“只清空当前月”。
- CloudBase 测试域名风险提示仍存在时，App 内不应过度承诺“绝对安全”，只表达“数据保存状态清楚、可导出备份”。
